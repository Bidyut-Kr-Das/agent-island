# Away Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An island `Away` switch. With Away off, Telegram is silent and everything stays instant on the PC. With Away on, everything goes to Telegram, including AskUserQuestion dialogs answered from the phone. The settings card is redrawn in the chosen style A.

**Architecture:** One shared `away: Arc<AtomicBool>` replaces the gate-pause flag. It is read by the pipe server (wait 600 s instead of 30 s, hold questions) and by `Phone` (send only while away).

A held question uses the existing request/reply path:
1. The hook sends `"ask": true`.
2. The island answers with the collected answers.
3. The hook prints `permissionDecision: allow` + `updatedInput.answers`. The spike proved this skips the dialog.

Turning Away off releases waiting work through a new `Reply::Rearm` (cards get a fresh 30 s) and by dropping question reply senders (the dialog opens in the terminal).

**Tech Stack:** Rust 2024, egui, serde_json; Telegram Bot API through the existing `src/telegram.rs`.

**Spec:** `docs/superpowers/specs/2026-11-18-away-mode-design.md` (builds on `2026-11-17-telegram-phone-design.md`)

## Global Constraints

- Away off: Telegram sends nothing from `Phone::on_event`. Pairing replies, tap acks and delivery of phone replies still work.
- Away off: questions are never held; permission and gated cards wait 30 s, as today.
- Away on: permission requests, gated commands and questions wait up to 600 s.
- Wait limits:
  - Hook client read: 605 s.
  - `hooks.json` `PreToolUse` and `PermissionRequest` timeout: 610.
- Away can be on only while `PhoneStatus::Paired`. Disconnect, or a token cleared to empty, turns Away off and releases everything waiting.
- Turning Away off releases everything waiting:
  - Questions: the hook prints nothing, so the dialog opens in the terminal.
  - Permission and gated cards: a fresh 30 s island wait.
- Away is persisted in `settings.json`, key `away` (bool), read-modify-write via `settings::set`.
- `Gating Paused` (skip the gate) is removed entirely. The island never replies `skip` to a gated hook again.
- Gated timeout deny reason, exact: `No answer in Agent Islands in time`.
- Never edit or delete a sent Telegram message. Multi-select state is shown in the tap ack, not by editing buttons.
- Copy, exact:
  - `Away`, `Send everything to Telegram`, `Pair a phone first`, `Phone paired`, `Not paired`, `Disconnect`, `Settings`, `Left`, `Right`, `Side`.
  - `Done`, `Which question?`, `Picked: <labels joined by ", ">`, `Too late, answered in the terminal`, `Already answered`.
- Answer formats (spike-confirmed for single-select). The `answers` map is keyed by the exact question text:
  - Single-select: the label.
  - Multi-select: labels joined by `, `.
  - Other: the typed text.
- Settings card style A: all exact values are in the spec's "Settings card visuals" section. Controls are right-aligned to the card's padding.
- Plain text, no emoji except colour circles. No new dependencies. No test touches the network or the real settings file.

## Review Focus

1. **Away flipped off while a question waits, and the phone answer arrives after.** Expected: the dialog already opened in the terminal; the late tap gets `Too late, answered in the terminal`, never a stray answer. Test: Task 4 `answer_after_release_is_too_late`.
2. **Two sessions each ask a question at once, and plain text arrives.** Expected: `Which question?` with one button per waiting question, and never a guess. Test: Task 5 `two_waiting_questions_ask_which`.
3. **A question with a multi-select and a normal question in one call.** Expected: both answered in order, and one hook reply with both keys. Test: Task 5 `two_questions_answer_in_order`.
4. **A gated card waiting 600 s when Away is turned off.** Expected: it now times out 30 s after the switch, not 600 s after it appeared. Test: Task 2 `rearm_restarts_with_30s`.
5. **Disconnect while away.** Expected: Away turns off, everything is released, and Telegram goes silent. Test: Task 3 `disconnect_turns_away_off_and_releases`.

### Task 2: Server and hook timing; gate pause removed

**Files:**
- Modify: `src/hook.rs` (`Reply`, `read_reply` 35 to 605 s, `pretool_output` timeout reason, `run_with`/`forward` ask envelope)
- Modify: `src/server.rs` (`paused` becomes `away`, wait loop, ask branch)
- Modify: `plugin/hooks/hooks.json` (two timeouts 40 to 610)

**Interfaces:**
- Produces:
  - `pub enum Reply { Allow, Deny, Rearm, Answer(serde_json::Value) }` in `src/hook.rs`. `Answer` holds the answers map.
  - `server::spawn(tx, wake, away: Arc<AtomicBool>)`.
  - The waiting thread starts with `30 s` or `600 s` (by `away` at arrival). `Reply::Rearm` restarts the wait at 30 s.
  - Pipe replies (hook side): `{"decision":"allow"|"deny"|"timeout"}` as today, plus `{"decision":"answer","answers":{...}}` and `{"decision":"skip"}`. `skip` is now only "do not hold this question".
  - Hook envelope for `PreToolUse` with `tool_name == "AskUserQuestion"`: adds `"ask": true` and waits for the reply.
  - Hook output for `answer`: `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow","updatedInput":{"questions":<event tool_input.questions>,"answers":<answers>}}}`. Any other reply, or none: prints nothing.
  - Server ask branch:
    - `ask && !away`: writes `skip` and passes the event on with `reply: None`.
    - `ask && away`: holds like a card. `Reply::Answer` writes `answer`. Disconnected or `Rearm` writes `skip`. Timeout writes nothing and sends `Msg::Timeout(id)`.

### Task 6: Settings card style A

**Files:**
- Modify: `src/ui/views.rs` (`settings_card`, `settings_h`), `src/ui/mod.rs` (call site)

**Interfaces:**
- Consumes: `PhoneStatus`, `Core::set_away`, `Core::disconnect` (Task 3).
- Produces: `settings_card(ui, pill: Rect, side: Side, away: bool, phone: &PhoneStatus) -> (Rect, Option<Side>, Option<bool> /* away clicked */, bool /* disconnect */)`.
  - Rows and values exactly as the spec's style A.
  - `Off`: Side only.
  - `Pairing`: Away disabled with `Pair a phone first`, plus the Phone row `Not paired`.
  - `Paired`: Away enabled, plus `Phone paired` and a `Disconnect` link.
  - `fn settings_h(phone: &PhoneStatus) -> f32`.
  - A pure `fn settings_layout(card: Rect, phone: &PhoneStatus) -> SettingsLayout` returns each control's rect, so alignment is testable.

  - **Pill outline jaggies (user report, screenshot: the amber outline is pixelated at the bottom).**
    - Root cause: `views::region` clips the window to exactly the pill's round-rect with a GDI region. GDI regions are not antialiased, so the region cuts egui's antialiased edge stroke. The bottom is worst because the pill height animates to fractional pixels.
    - Fix: `region` grows each shape by 2 logical px on every side (radius + 2) before converting, so the stroke's soft edge sits inside the window.
